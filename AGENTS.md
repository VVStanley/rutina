# Рутина — инструкции по проекту

## Назначение и постоянные ограничения

- «Рутина» — приложение для семейного бюджета, покупок, дел, заметок и календаря с напоминаниями.
- Текущая цель — личное и семейное использование на Android; результат для установки и проверки — APK.
- Поддерживать русский и английский интерфейсы. Пользовательские записи автоматически не переводить.
- Целевые устройства включают Huawei P60 и другие Android-телефоны. Основные функции не должны требовать Google Play services; совместимость проверять на устройстве.
- Без сети доступен просмотр сохранённых данных. Добавление записей и любые другие изменения требуют доступного сервера; подробности — в [PRODUCT.md](docs/PRODUCT.md#работа-без-сети).
- Дом — изолированное пространство с общими для его участников данными и одним администратором.
- Только управляющий приложением создаёт дома и назначает их администраторов. Эта роль не даёт доступа к содержимому чужих домов.
- Подробные права участников и исключения определены в [PRODUCT.md](docs/PRODUCT.md). Не расширять их по аналогии с другими приложениями.
- Публичный выпуск, другие клиентские платформы, реклама и оплата находятся вне текущего объёма.

## Подход к разработке

- Общаться с пользователем на русском; документацию проекта вести на русском.
- Перед изменениями читать относящиеся к задаче документы и реализацию.
- Выполнять минимальное законченное изменение; не придумывать продуктовые правила и функции на будущее.
- Разделять интерфейс, прикладную логику, хранение данных и внешние интеграции без лишних слоёв и пустых расширений.
- Размещать код по [структуре проекта](docs/ARCHITECTURE.md#структура-проекта). При изменении штатных команд обновлять `Makefile` и [README.md](README.md).
- Использовать согласованный стек из [ARCHITECTURE.md](docs/ARCHITECTURE.md); его замену согласовывать.
- Нерешённые вопросы не превращать в требования. Перед реализацией зависимого поведения получать решение пользователя.
- До реализации пользовательских экранов выбранного этапа согласовывать дизайн по [DESIGN.md](docs/DESIGN.md). Дизайн опирается на продуктовые требования и не вводит новые правила без обсуждения.
- Обсуждение, согласие с формулировкой и обновление документации сами по себе не разрешают начинать реализацию приложения.
- После согласованного изменения актуализировать затронутые документы; не дублировать изменяемые подробности в AGENTS.md.
- Противоречия требований и кода обозначать явно, не разрешать молчаливой сменой поведения.
- При продолжении реализации, запросе статуса, подготовке или проверке подплана и планировании исправлений по ревью применять [$rutina-plan](.agents/skills/rutina-plan/SKILL.md).

## Разрешения и данные

- Следовать общим рабочим инструкциям пользователя; проектные документы не расширяют разрешения.
- Проверять Git-состояние, включая новые файлы; сохранять существующие изменения. При недоступном Git использовать сравнение с исходным содержимым.
- Установка и обновление зависимостей, действия с индексом и историей Git, push, публикация, развёртывание и изменения production требуют явного поручения.
- Внешние обращения требуют разрешения, кроме чтения публичной технической документации без передачи данных проекта; учитывать прямые разрешения пользователя.
- Не помещать секреты и реальные семейные данные в код, логи, примеры и тестовые артефакты. Использовать вымышленные тестовые данные.
- Не передавать семейные данные внешним сервисам без явного разрешения. Не подключать рекламные и аналитические SDK заранее.
- Проверять доступ на сервере, включая выборки списков и синхронизацию; ограничения интерфейса не заменяют проверки прав.

## Проверка результата

- При изменении кода соблюдать [CODING_STANDARDS.md](docs/CODING_STANDARDS.md). После реализации сразу запускать форматтер и линтер, исправлять все замечания в области задачи и повторять проверки после исправлений.
- Перед завершением изменений кода и при отдельной проверке соблюдения правил применять [$rutina-code-validation](.agents/skills/rutina-code-validation/SKILL.md).
- При отдельном ревью изменений или перепроверке замечаний применять [$rutina-review](.agents/skills/rutina-review/SKILL.md).
- При подготовке APK к приёмке и разборе прогона на телефонах применять [$rutina-android-qa](.agents/skills/rutina-android-qa/SKILL.md).
- Каждый этап должен иметь наблюдаемый результат, критерии готовности и способ проверки.
- Проверки выбирать по изменению; изучать их подключения и побочные эффекты перед запуском.
- Для затронутых сценариев проверять изоляцию домов, авторство, права, повторную отправку и работу без сети.
- Для Android проверять сборку и поведение на целевом телефоне; эмулятор и сборка APK не заменяют проверку устройства.
- Проверять русский и английский интерфейсы и сохранность данных при затронутых обновлениях.
- Перед завершением просматривать итоговые изменения и новые файлы. Явно сообщать, что выполнено и что осталось непроверенным.
