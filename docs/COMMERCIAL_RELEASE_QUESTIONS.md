# Вопросы перед возможным коммерческим выпуском

## Статус и границы

Этот документ содержит вопросы, к которым пользователь решил вернуться, только если будет принято отдельное решение развивать «Рутину» для продажи или публичного использования.

Коммерческий выпуск не запланирован. Вопросы ниже не блокируют личный MVP, не являются утверждёнными будущими функциями и не требуют предварительных компонентов в коде. Право создавать дома остаётся только у управляющего приложением.

Текущие требования находятся в [PRODUCT.md](PRODUCT.md), активные брифы — в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md), остальные отложенные вопросы и проработка после MVP — в [DEFERRED_QUESTIONS.md](DEFERRED_QUESTIONS.md).

## C01. Модель аккаунтов и участия в домах

- Статус: **Отложен до решения о коммерческом развитии**.
- Источник: **B02.3**.
- Текущее решение для MVP: один дом на учётную запись, без переключения аккаунтов. Если при добавлении нового участника почта уже зарегистрирована, показываем красным сообщение «Эта почта уже зарегистрирована. Укажите другую.» и не создаём нового участника по этому действию.
- Неактивного участника того же дома администратор может включить отдельно с прежней учётной записью. Ошибка при добавлении нового пользователя не отменяет эту возможность.
- Что проработать: нужна ли одна учётная запись в нескольких домах, несколько аккаунтов с переключением или иной сценарий. Термин «мультиаккаунт» не определяет автоматически выбранную модель. Также определить поведение приглашения существующей учётной записи, сохранив изоляцию семейных данных.
- Когда вернуться: только после отдельного решения о коммерческом развитии.
- Блокирует MVP: **нет**.

## C02. Смена почты, выход и управление устройствами

- Статус: **Отложен до решения о коммерческом развитии**.
- Источник: **B02.5**.
- Текущее решение для MVP: нет пользовательских функций смены почты, выхода из аккаунта и управления входами на устройствах. Не добавлять соответствующие экраны заранее.
- Что проработать: смена и подтверждение почты, выход из аккаунта, просмотр устройств и отзыв доступа на потерянном телефоне, судьба локальных несинхронизированных данных при этих действиях.
- Когда вернуться: только после отдельного решения о коммерческом развитии.
- Блокирует MVP: **нет**.

В текущем MVP вход сохраняется между обычными запусками и после перезагрузки телефона. После успешного сброса пароля все прежние сессии аннулируются и на каждом устройстве требуется новый вход. Серверная проверка сессии и статуса участника также нужна текущему приложению; она не откладывается вместе с пользовательским экраном управления устройствами. Эти согласованные правила B02.4–B02.5 не означают добавления экрана управления сессиями.

## C03. Восстановление без доступа к почте

- Статус: **Отложен до решения о коммерческом развитии**.
- Источник: **B02.4**.
- Текущее решение для MVP: если одновременно забыты пароль и доступ к почте, пользователь сначала восстанавливает почтовый ящик у почтового сервиса. Затем администратор или управляющий отправляет нашу ссылку сброса в пределах своих полномочий. Если почту восстановить невозможно, обходного сброса в MVP нет. При известном пароле обычный вход остаётся доступным по общим правилам.
- Что проработать: альтернативное подтверждение владельца и восстановление при недоступной почте, полномочия управляющего и администратора, связь со сменой почты из C02, последствия для сессий и защита семейных данных.
- Когда вернуться: только после отдельного решения о коммерческом развитии.
- Блокирует MVP: **нет**.

## Как пополнять документ

Сохранять постоянные номера Cxx, источник вопроса, правило текущего MVP и условие возвращения. После обсуждения по поручению пользователя переносить подтверждённое решение в продуктовые и технические документы, оставляя здесь ссылку. Не реализовывать неподтверждённые варианты по одному факту их перечисления.
