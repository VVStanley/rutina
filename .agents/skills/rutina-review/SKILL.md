# Ревью кода «Рутины»

## Область и глубина

- Прочитать [AGENTS.md](../../../AGENTS.md), запрос, соответствующий шаг [основного плана](../../../plans/MASTER_PLAN.md) и затронутые требования. Сверить с [правилами кода](../../../docs/CODING_STANDARDS.md) и [архитектурой](../../../docs/ARCHITECTURE.md). Для ревью плана использовать [rutina-plan](../rutina-plan/SKILL.md#проверить-готовность-подплана).
- Установить версию и область ревью. Учитывать новые файлы, относящиеся к задаче. При проверке ветки использовать согласованную базу сравнения. Вне Git использовать доступную исходную версию и явно указать ограничение, если базы нет. Пустой diff не расширяет ревью на весь проект.
- В обычном режиме проверить изменённый путь, его ближайших потребителей и существенные критерии шага. В углублённом режиме по запросу проследить затронутые входы и записи до конечного результата, включая соседние сценарии, API и сохранённые данные, которые зависят от изменения.

## Проверка изменений

1. Сначала проверить достижимые риски потери данных и нарушений доступа к дому, затем корректность остальных затронутых сценариев. Для операции записи рассмотреть роль и исходное состояние, повтор запроса, конкурентное изменение, потерю ответа и откат по применимости. Для Android проверить значимые состояния экрана, чтение без сети и сохранение ввода при отказе, когда они затронуты.
2. Проверить владельца бизнес-правила, направление зависимостей и границу транзакции. Для смены API или схемы проверить затронутых потребителей и сохранность данных прежней версии. Замечание о сложности подкрепить конкретным последствием и показать простое достаточное изменение, сохраняющее требования.
3. Сопоставить тесты с критериями и реальным путём выполнения. Успешный тест подтверждает только проверенные им условия. Результаты прежних проверок использовать только при совпадающих версии, окружении и области. При существенном пробеле выполнить подходящую локальную проверку без автоисправлений. Сбой окружения и непроверенный сценарий указать отдельно от дефектов.

## Перепроверка замечаний

Для каждого замечания проследить условие, путь выполнения, действующие проверки и результат. Попытаться опровергнуть вывод. Установить, подтверждается ли он, уже исправлен, опровергнут или требует дополнительных данных. Сохранять исходный номер замечания, если он есть. При сомнении о происхождении дефекта назвать границы сравнения с исходной версией. Для плана исправлений передать подтверждённые проблемы в [rutina-plan](../rutina-plan/SKILL.md#спланировать-исправления-по-ревью).

## Итог

Сначала перечислить подтверждённые замечания по серьёзности с файлом и строкой, условием проявления, нарушенным требованием и наблюдаемым последствием. Для нескольких находок без исходных номеров использовать `REV-1`, `REV-2` и далее. Отдельно указать существенные гипотезы и реально выполненные проверки. Если замечаний нет, назвать проверенную область и оставшиеся ограничения. Ревью выполняется без изменения исходников и без внешней публикации результатов.
