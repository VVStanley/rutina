# Приёмка Android «Рутины»

1. Определить проверяемый шаг и его критерии по [основному плану](../../../plans/MASTER_PLAN.md), подплану, [ROADMAP.md](../../../docs/ROADMAP.md) и [AGENTS.md](../../../AGENTS.md). Выбрать сценарии, которые подтверждают результат шага, и связанную регрессию по затронутым данным, правам и пользовательским путям. Для каждого сценария указать исходное состояние, роль, действия и ожидаемый результат.
2. Подготовить APK штатной командой из [README.md](../../../README.md), если имеются исходники, зависимости и доступное окружение. Проверить нужные настройки тестового API и подготовить вымышленные данные по плану. Указать путь к фактическому APK и версию проверенной сборки или точный блокер. Для проверки на двух телефонах указывать один и тот же APK.
3. Передать пользователю короткий чек-лист установки и прогона. Для [1.1](../../../plans/1.1-environment.md#проверка-и-завершение) использовать один Huawei P60, локальный API, обрыв и восстановление связи и оба системных языка. Для [1.4](../../../plans/MASTER_PLAN.md#14-просмотр-без-сети-и-приёмка-p2) использовать два P60, сохранение покупки на одном, обновление списка на другом, чтение после перезапуска без сети и отказ при попытке записи без связи. Для других шагов брать сценарии из соответствующего плана.
4. Отдельно сообщить результат сборки и фактический результат каждого телефонного сценария. Прогон на устройствах выполняет пользователь. Присваивать сценарию результат по его наблюдениям. Если наблюдений ещё нет, телефонная проверка ожидается. При сбое собрать условия, ожидаемый и фактический результат. Обязательный непроверенный сценарий оставляет приёмку открытой.
5. При работе над реализацией по плану либо по поручению обновить запись о проверках в подплане и статус по [rutina-plan](../rutina-plan/SKILL.md). Отчёта в чате достаточно для подготовки чек-листа и обсуждения результата.
