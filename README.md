# Рутина

Android-приложение для семейного бюджета и организации домашних дел: доходы, расходы, обязательные платежи, запланированные и купленные покупки, дела, заметки и календарь с напоминаниями.

## Состояние проекта

Каркас с `GET /health` и диагностическим экраном Android принят на Huawei P60. Пользователь повторно проверил сборку `0.1.3` после исправлений по ревью. [Результаты проверки](plans/1.1-environment.md#повторная-проверка-после-ревью)

Текущий шаг — [1.2. Вход и изоляция домов](plans/1.2-login.md).

Текущий объём — личное и семейное использование. Пользователи входят под собственными учётными записями в отдельные дома. Внутри дома данные общие, между домами изолированы. Создание домов остаётся за управляющим приложением.

Первая платформа — Android, языки интерфейса — русский и английский. Без сети доступен просмотр ранее загруженных данных; добавление, редактирование, отметки и удаление требуют доступного сервера. Приложение показывает время последнего успешного обновления данных, например «Обновлено сегодня в 12:30». Постоянный мониторинг доступности сервера не требуется. Первый APK рассчитан на Android 12 и новее, целевые устройства — два Huawei P60.

## Согласованный стек

- Android: Kotlin, Jetpack Compose, Room, WorkManager.
- Сервер: Python, FastAPI, Pydantic, SQLAlchemy, Alembic.
- Серверная база: PostgreSQL.
- Серверное окружение локально и на одном рабочем сервере: Docker Compose.

Серверная сборка использует Python 3.13.15, `uv` 0.12.7 и PostgreSQL 17. Для локальных проверок Python нужен интерпретатор 3.13. Версии Gradle 8.13, AGP 8.13.2, Kotlin 2.3.21, Compose BOM `2026.04.01` и ktlint 1.8.0 зафиксированы в конфигурации Android. Для сборки нужны JDK 17, Android SDK Platform 36 и Build Tools 35.0.0. Указать SDK через `ANDROID_HOME` или `sdk.dir` в `android/local.properties`. Для установки по USB нужны Platform Tools (`adb`). [Архитектура](docs/ARCHITECTURE.md#версии-для-первой-сборки)

## Локальный запуск API

Требуются Docker Engine с BuildKit и Docker Compose v2. Скопируйте `.env.example` в `.env` и задайте новый пароль вымышленной локальной БД в `RUTINA_DATABASE_PASSWORD`. Файл `.env` хранится вне Git.

```bash
make up
curl -i http://127.0.0.1:8000/health
make status
make logs
```

`make up` ждёт готовности PostgreSQL и API. При работающей БД запрос возвращает `204 No Content` и `X-Request-ID`. Тот же идентификатор есть в журнале API. OpenAPI и Swagger UI доступны по `/openapi.json` и `/docs`. `make down` останавливает сервисы и сохраняет том БД проекта `rutina-local`.

Если Docker исчерпал пул подсетей, выберите свободную подсеть, которая не пересекается с маршрутами компьютера и существующими Docker-сетями. Запишите её в `compose.local.network.yaml` по схеме ниже и повторите `make up`. Makefile подхватывает этот файл автоматически. [Настройки сетей Compose](https://docs.docker.com/reference/compose-file/networks/#ipam)

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 10.254.240.0/28
```

Для теста с телефона задайте в `.env` `RUTINA_API_BIND_ADDRESS` равным LAN-адресу компьютера и запустите `make up` снова. Используйте этот адрес вместо `127.0.0.1` в запросе и при сборке тестового APK. Телефон и компьютер должны быть доступны друг другу в домашней сети.

## Проверки и тестовый APK

- `make help` показывает доступные команды.
- `make fmt` запускает Ruff и `ktlintFormat`.
- `make check` проверяет форматирование, Ruff, mypy, `ktlintCheck` и Android Lint.
- `make test` запускает модульные тесты Python и Kotlin и интеграционный тест Python. `make test-db` отдельно запускает интеграционный тест в одноразовом Compose-проекте с пустой PostgreSQL и без опубликованных портов.

Тестовая серия использует `applicationId` `app.rutina.test`. Семейная серия зарезервирована под `app.rutina` с отдельным ключом. Для первой тестовой сборки один раз создайте ключ в приватном каталоге вне репозитория и сохраните его резервную копию. Путь и пароль установите в переменных `RUTINA_TEST_KEYSTORE` и `RUTINA_TEST_KEYSTORE_PASSWORD`. Для существующей тестовой серии используйте прежний ключ.

```bash
keytool -genkeypair -storetype PKCS12 -keystore "$RUTINA_TEST_KEYSTORE" \
  -alias rutina-test -keyalg RSA -keysize 2048 -validity 10000
```

Пример сборки для телефона с адресом компьютера `192.168.1.10`. Для каждой следующей выдаваемой сборки увеличивайте `rutinaTestVersionCode`. Незашифрованный HTTP разрешён в тестовой отладочной сборке.

```bash
ORG_GRADLE_PROJECT_rutinaApiBaseUrl=http://192.168.1.10:8000 \
ORG_GRADLE_PROJECT_rutinaTestVersionCode=1 make apk
```

Подписанный APK появляется в `android/app/build/outputs/apk/debug/app-debug.apk`. Сохраните первый APK отдельно перед сборкой второго, чтобы проверить обновление. [Проверка на Huawei P60](plans/1.1-environment.md#приёмка-на-huawei-p60)

## Следующий шаг

Для продолжения в новом чате использовать [готовый бриф и стартовое сообщение](docs/BRIEFS.md#как-пользоваться). Переносить историю обсуждения не требуется.

B01–B07 завершены для текущего MVP с явно отложенными расширениями. Согласованы карточки членов семьи, получатели покупок, единая модель расходов, динамические отчёты, возвраты и ограничения удаления; авторство финансовых записей отменено. B05 определил ежемесячные и ежегодные платежи, ориентиры по месяцам и копирование прошлогодних фактических сумм, сводку предстоящих обязательств, календарный просмотр, просрочку и остановку повторений любым участником с подтверждением. Подробные правила — в [PRODUCT.md](docs/PRODUCT.md#обязательные-платежи).

B06 определил дела с датой или без неё, принадлежность семье или члену семьи, повторение от фактического выполнения, состав календаря и единые напоминания: показ на главном экране за 3 дня, одно тихое уведомление всем участникам за 2 дня в 10:00 по времени дома. Для повторения нужна дата первого события. Подробности — в [PRODUCT.md](docs/PRODUCT.md#календарь-и-напоминания).

Дополнение B06.6 определило [покупки, связанные с делом](docs/PRODUCT.md#покупки-связанные-с-делом): несколько покупок у дела, максимум одно дело у покупки, создание, выбор существующих и редактирование прямо из дела. Статусы, даты и напоминания независимы, для следующего повторения покупки добавляются вручную. Отвязка и удаление связанного объекта сохраняют другую запись с учётом прежних прав и ограничений удаления.

B07 завершён для MVP: определены проверка версии всей записи и понятное разрешение конфликтов, одинаковые повторные отметки без дублей, отказы и проверка потерянного ответа, доступ неактивного участника, обновление данных и экономия трафика. Полные правила — в [PRODUCT.md](docs/PRODUCT.md#работа-без-сети). Схема API, частота фона и параметры повторов выбираются перед реализацией; код ещё не создан.

B08 завершён для MVP. [Правила хранения на телефоне](docs/PRODUCT.md#хранение-данных-на-телефоне) ограничивают объём локальной копии и определяют её сохранность после перезапуска и обновления. Отчёты пересчитываются по записям выбранного периода. Корзина и черновики отложены, [резервирование](docs/DEFERRED_QUESTIONS.md#d07-резервное-копирование-перед-семейным-запуском) настраивается перед вводом реальных семейных данных. B09 завершён.
